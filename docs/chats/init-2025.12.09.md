### API Endpoints Design

#### 1. Configuration Management

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/config` | Get current configuration |
| `PATCH` | `/config` | Update configuration (partial) |
| `POST` | `/config/reset` | Reset to defaults from .env |

**Config Object:**
```json
{
  "candle_interval_minutes": 5,
  "max_tickers": 50,
  "max_candles_stored": 100,
  "auto_reconnect": true,
  "reconnect_delay_seconds": 5,
  "persist_data": true,
  "market_hours_only": false
}
```

#### 2. Ticker Management

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/tickers` | List all tracked tickers with status |
| `POST` | `/tickers` | Add ticker(s) |
| `DELETE` | `/tickers/{ticker}` | Remove single ticker |
| `DELETE` | `/tickers` | Remove multiple tickers (body) |
| `POST` | `/tickers/validate` | Validate ticker symbols |

**Example Responses:**
```json
// GET /tickers
{
  "count": 5,
  "max_allowed": 50,
  "tickers": [
    {"symbol": "AAPL", "status": "active", "last_tick": "2025-12-09T14:30:00Z", "candle_count": 15},
    {"symbol": "MCD", "status": "active", "last_tick": "2025-12-09T14:29:55Z", "candle_count": 15},
    {"symbol": "INVALID", "status": "no_data", "last_tick": null, "candle_count": 0}
  ]
}

// POST /tickers - Add tickers
Request: {"tickers": ["TSLA", "NVDA"]}
Response: {"added": ["TSLA", "NVDA"], "rejected": [], "current_count": 7}
```

#### 3. Candle Data

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/candles/{ticker}` | Get candles for single ticker |
| `POST` | `/candles/multi` | Get candles for multiple tickers |
| `GET` | `/candles/{ticker}/latest` | Get only current (incomplete) candle |
| `DELETE` | `/candles/{ticker}` | Clear candle history for ticker |
| `DELETE` | `/candles` | Clear all candle history |

**Query Parameters for `/candles/{ticker}`:**
- `count` - Number of candles (default: 10)
- `include_current` - Include incomplete candle (default: true)
- `from_timestamp` - Filter from Unix timestamp
- `to_timestamp` - Filter to Unix timestamp

#### 4. System Status

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/health` | Basic health check |
| `GET` | `/status` | Detailed system status |
| `GET` | `/metrics` | Prometheus-format metrics |
| `POST` | `/reconnect` | Force WebSocket reconnection |

### Environment Variables (.env)

```bash
# === EODHD API ===
EODHD_API_KEY=your_api_key_here

# === HTTP Server ===
HTTP_HOST=0.0.0.0
HTTP_PORT=8765
API_KEY=                          # Optional: Require API key for requests

# === Default Tickers ===
DEFAULT_TICKERS=AAPL,MSFT,GOOGL,TSLA,NVDA

# === Candle Configuration ===
CANDLE_INTERVAL_MINUTES=5         # 1, 5, 15, 30, 60
MAX_CANDLES_STORED=100            # Per ticker
MAX_TICKERS=50                    # EODHD WebSocket limit

# === WebSocket ===
WS_RECONNECT_DELAY=5              # Seconds
WS_PING_INTERVAL=30               # Keep-alive ping

# === Data Persistence ===
PERSIST_DATA=true                 # Save candles to disk
DATA_FILE=/data/candles.json      # Persistence file path
CONFIG_FILE=/data/config.json     # Runtime config persistence

# === Market Hours ===
MARKET_HOURS_ONLY=false           # Only collect during market hours
CLEAR_ON_MARKET_CLOSE=false       # Clear candles at market close

# === Logging ===
LOG_LEVEL=INFO                    # DEBUG, INFO, WARNING, ERROR
LOG_FORMAT=json                   # json or text
```

### Suggested Improvements

#### 1. **Data Persistence**
- Save candles to JSON file or SQLite database
- Survive container restarts without losing data
- Configurable retention period

#### 2. **Multi-Interval Support**
- Track multiple intervals simultaneously (1m, 5m, 15m)
- Derive larger intervals from smaller ones
```json
GET /candles/AAPL?interval=5m
GET /candles/AAPL?interval=15m
```

#### 3. **WebSocket Output (Push to n8n)**
- Expose WebSocket endpoint for clients
- n8n can subscribe to real-time candle completion events
- Eliminates polling
```
ws://localhost:8765/ws/candles
Message: {"event": "candle_complete", "ticker": "AAPL", "candle": {...}}
```

#### 4. **Technical Indicators**
- Calculate common indicators on-the-fly:
  - SMA/EMA (5, 10, 20 periods)
  - RSI
  - VWAP
```json
GET /candles/AAPL?indicators=sma_5,rsi_14,vwap
```

#### 5. **Alerts/Webhooks**
- Configure price/volume alerts
- Send webhook to n8n when triggered
```json
POST /alerts
{
  "ticker": "AAPL",
  "condition": "price_above",
  "value": 250.00,
  "webhook_url": "http://n8n:5678/webhook/price-alert"
}
```

#### 6. **Rate Limiting & Security**
- Optional API key authentication
- Rate limiting per IP/key
- IP whitelist for n8n server only

#### 7. **Market Hours Awareness**
- Auto-detect US market schedule
- Handle holidays
- Separate pre-market/regular/after-hours data
```json
{
  "candle": {...},
  "session": "pre_market"  // "regular", "after_hours", "closed"
}
```

#### 8. **Dead Ticker Detection**
- Flag tickers with no ticks for X minutes
- Auto-remove or alert on dead tickers
- Useful for detecting delisted/halted stocks

#### 9. **Batch Operations**
- Import/export ticker lists
- Backup/restore all data
```
POST /tickers/import   (CSV or JSON)
GET  /tickers/export
POST /backup
POST /restore
```

#### 10. **Docker Health Improvements**
- Proper health check that verifies WebSocket connection
- Graceful shutdown (complete current candle)
- Resource limits in docker-compose
